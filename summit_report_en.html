The Summit and Day 1

Result 1: AI-assisted developer experience (Developer Web Console and MCP)

The main theme of Day 1 was a refreshed developer experience built around AI agents. A new browser-based Developer Web Console (developers.minepi.com) and an MCP (Model Context Protocol) server connect compatible AI coding agents to Pi's developer tools. Given natural-language instructions, an agent can create and register a Pi application, configure its settings and URLs, integrate Pi APIs such as Pi Authentication and Pi Payments, and apply for listing in the Pi app directory. Secrets (API keys and wallet private keys) are kept from the agent by design, and human authorization is required where needed. The same console also supports traditional manual workflows.

In a demo by founder Nicolas Kokkalis, an AI agent built a tic-tac-toe game ("Pocket Grid") from scratch. The steps shown were as follows.

  • The agent built the game and deployed it to a public HTTPS URL. At this stage it was an ordinary app with no Pi integration.
  • The agent connected to Pi's MCP server and registered the app. It loaded the app in Pi Sandbox (a development environment that emulates the Pi Browser) and verified that it worked.
  • Multiplayer was added. One player creates a room and invites a friend through a PiNet link (a URL ending in pinet.com). Opening a PiNet link opens the app in the Pi Browser.
  • Notifications were added so a player is notified when their turn arrives. Server-to-server communication uses an API key, which the developer generates in the console and stores securely.
  • Pi Payments were added. Creating a room charges 1 Pi, with a refund if nobody joins. The demo showed both directions: user to app, and app back to user as a refund. This was on Testnet, and the app wallet's private key was kept by the developer, not given to the agent.
  • Finally, the steps to submit the app for listing were shown. Much of the submission had already been prepared by the agent.

The demo showed the multiplayer build taking about 10 minutes. The blog post likewise describes steps that used to take days now taking minutes.

Result 2: On-chain subscriptions and x402 payments (demonstrated on Testnet)

On-chain subscription smart contracts

Pi's on-chain subscription smart contract lets developers build recurring payment services into their applications. It was first introduced on Pi Testnet in April 2026. A user approves a defined spending budget and subscription period (for example, 6 months for a monthly subscription) without signing every renewal. Approved funds remain in the user's own wallet until each payment is processed, rather than being locked or transferred upfront. Users can extend or cancel their subscriptions. The contract data is managed through two records (the service offering and each user's subscription state) and remains on-chain for around 180 days.

The Day 1 demo created a service priced at 2 Pi per month (service ID 332), showed a user subscribing, and checked the subscription state in the wallet. In the demo example, the merchant could process the next cycle's charge between December 10 and January 10. Subscriptions are currently available only on Testnet. According to the blog post, the supporting infrastructure in Pi Wallet and the developer platform has now been implemented so both users and developers can use the full experience.

x402 payments integrated on Pi Testnet

x402 is an open payment protocol that uses the HTTP 402 (Payment Required) response. A server states the price, asset, and recipient; the client signs a payment approval and resends the request; a facilitator verifies the approval and submits it to the chain. Funds move directly from payer to recipient in a single on-chain transaction, and the facilitator never holds the funds. The standard was created by Coinbase and is maintained by the x402 Foundation.

Pi has made x402 payments available on Pi Testnet. Day 1 featured a demonstration by OpenMind, together with the Fabric Foundation, of its RoboPay platform. A ping command to a robot was paid for with 0.01 Test Pi before the command was delivered, and only after the payment completed. The network fee was sponsored, so the payer's balance changed by exactly minus 0.01 Test Pi. Pi's network ID (pinet) has been merged into the Chain Agnostic registry, and Pi's x402 payment specification has been submitted to the official x402 repository, where it is under review. The specification covers both Testnet and Mainnet, while details on Mainnet availability will be shared later. A Go SDK implementing the specification is also available.

Result 3: Ecosystem initiatives (growth support, app directory, Launchpad)

App Growth Initiative (up to 20 million Pi)

A new initiative sponsored by the Pi Foundation, the "App Growth Initiative", was announced, with a marketing budget of up to 20 million Pi. Eligible developers can qualify for access to a portion of this budget based on the merits and performance of their applications, and use the Pi-funded incentive program to reach and engage KYC-verified users without funding the rewards themselves. As an example, when an eligible KYC-verified Pioneer invites another eligible KYC-verified Pioneer to use a participating app, both the referring Pioneer and the new user could each receive some Pi from the Foundation-sponsored incentive budget for qualifying participation. Exact eligibility requirements and reward amounts will be announced later.

Redesigned Pi App Directory

The Pi App Directory was substantially redesigned. The existing "Ecosystem Directory Staking" mechanism, in which Pioneers stake Pi to support apps and influence ranking, remains central. New discovery sections based on user interest, growth, and engagement were added.

Developer incentives are built from visibility, financial support, and status. As one financial example, Pi App Studio applies subsidized pricing for creators whose apps demonstrate real utility and attract real users. Status is shown in the app directory, and strong apps may gain opportunities such as investment from Pi Network Ventures or candidacy for Launchpad.

Pi Launchpad, DEX, and AMM coming to Mainnet in Q1 2027

Pi Launchpad, decentralized exchange (DEX), and automated market maker (AMM) capabilities will launch on Mainnet in Q1 2027. They have been on Testnet through multiple cycles of iteration, and the launch includes the first Mainnet token launch through Launchpad. They will provide infrastructure for ecosystem token launches for specific utility purposes. The Q1 2027 timeline also gives potential Launchpad candidates, including participants in the upcoming Pi Next hackathon, time to build and prepare.

Other developer features

  • Improved PiNet deep linking: When someone opens a PiNet app link without Pi Browser installed, they are prompted to download Pi Browser from the App Store or Google Play. After installing and opening Pi Browser, they are redirected to the original app or page they intended to visit, so an invited person can play a game session directly without manual navigation.
  • Notification Center: Developers can send users ecosystem notifications from their Pi apps, shown in one place inside the Pi Browser. These are in-app notifications, not push notifications to phones. During the initial rollout, applications can send notifications to up to 20 users without additional approval; notifying more users requires approval. Native push notifications are the next step, subject to more selective and restrictive rules to prevent spam.

Result 4: Developer conversation (CiDi Games)

The second half of Day 1 featured a conversation between founder Chengdiao Fan and Jeremy, co-founder of CiDi Games. CiDi Games is an HTML5 game platform playable directly in the Pi Browser, built around its original character IP "Pi Elf" and its game world "Elf Continent". It has been live for about six months and remains in beta.

For the future, CiDi Games described opening Pi Elf art assets to third-party developers and mapping them onto the blockchain as NFTs, building full-stack tools such as an NFT launchpad and marketplace, and bringing its own native token to Pi Launchpad. These are the company's internal directions, however, and the token plan in particular was stated in the conversation as not yet discussed with the Pi Core Team. They are not confirmed announcements.

CiDi Games also described cooperation with the Pi Core Team, including a case in which players' KYC-related questions led to KYC survey questions being arranged and launched in less than two weeks. Fixes for iOS local-storage issues, a streamlined Mainnet verification process for new releases, and per-team advertising reporting were likewise made in response to developer feedback.

Fan described the broader strategy as connecting external demand to Pi's collective resources (distribution, attention, and user acquisition; human-in-the-loop work and data, with user consent; distributed computing; and identity). Gaming fits Pi well, she said, because payments run at scale on-chain, social interaction matches gaming, and games offer an easy on-ramp to financial participation. Stablecoin integration and further Web3 functionality are being considered within limits that do not compromise the central role of the Pi currency.
