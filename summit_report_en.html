About the Summit

The Pi Ecosystem Summit is Pi Network's first developer-focused summit, held online from November 17 to 19, 2026. Day 1 (November 17) covered the developer platform, ecosystem initiatives, and app showcases. The full Day 1 video premiered on Pi Network's official YouTube channel and runs 1 hour 45 minutes 5 seconds. Day 2 (November 18) covers AI and the ecosystem; Day 3 (November 19) kicks off the new hackathon "Pi Next" with a 200,000 USDT prize pool.

In her opening remarks, founder Chengdiao Fan cited the ecosystem's scale: over 60 million Engaged Pioneers, over 300 Mainnet apps, over 420,000 Nodes, and over 18.1 million fully KYC-verified users. These figures are as officially stated.

Result 1: AI-assisted developer experience (Developer Web Console and MCP)

The main theme of Day 1 was a refreshed developer experience built around AI agents. A new browser-based Developer Web Console (developers.minepi.com) and an MCP (Model Context Protocol) server connect compatible AI coding agents to Pi's developer tools. Given natural-language instructions, an agent can create and register a Pi application, configure its settings and URLs, integrate Pi APIs such as Pi Authentication and Pi Payments, and apply for listing in the Pi app directory. Secrets (API keys and wallet private keys) are kept from the agent by design, and human authorization is required where needed. The same console also supports traditional manual workflows.

In a demo by founder Nicolas Kokkalis, an AI agent built a tic-tac-toe game ("Pocket Grid") from scratch. The steps shown were as follows.

  • The agent built the game and deployed it to a public HTTPS URL. At this stage it was an ordinary app with no Pi integration.
  • The agent connected to Pi's MCP server and registered the app. It loaded the app in Pi Sandbox (a development environment that emulates the Pi Browser) and verified that it worked.
  • Multiplayer was added. One player creates a room and invites a friend through a PiNet link (a URL ending in pinet.com). Opening a PiNet link opens the app in the Pi Browser.
  • Notifications were added so a player is notified when their turn arrives. Server-to-server communication uses an API key, which the developer generates in the console and stores securely.
  • Pi Payments were added. Creating a room charges 1 Pi, with a refund if nobody joins. The demo showed both directions: user to app, and app back to user as a refund. This was on Testnet, and the app wallet's private key was kept by the developer, not given to the agent.
  • Finally, the steps to submit the app for listing were shown. Much of the submission had already been prepared by the agent.

The demo showed the multiplayer build taking about 10 minutes. The blog post likewise describes steps that used to take days now taking minutes.

Result 2: Pi DataLab (a new platform connecting human judgment with AI)

Pi DataLab is a new human-in-the-loop platform that lets businesses, AI developers, and other organizations request work requiring human judgment from identity-verified Pioneers around the world. Covered tasks include data generation, labeling, evaluation, ranking, review feedback, and physical AI data — work where quality depends on human understanding rather than automation alone. Clients create and fund projects, while participating Pioneers voluntarily choose tasks, contribute their judgment or work, and receive Pi or tokens for completed contributions.

The demo used customer-support ticket sentiment classification (positive, neutral, or negative) as an example and walked through project creation to publication. The project, named "ticket sentiment", requested five responses per task, with participation requirements including KYC verification, language, and geography, and was published after Pi's review. Once live, clients can monitor metrics such as average time to open and complete tasks and acceptance rates. On the task-doer side, a task marketplace shows the payout and estimated completion time for each task. Payouts are made monthly, according to the demo narration.

A quality layer records each task doer's reputation. Signals include genuine effort, time taken to open and complete tasks, submission attempts, and accuracy, and are used to maintain quality and inform future task assignments.

The first version is complete and runs in a testing environment. The demo took place in that staging environment, with payments disabled. The production pilot is expected to connect payments through Mainnet wallets. No release date was stated.

As background, Pi's KYC verification infrastructure has already coordinated more than 526 million validation tasks completed by over one million human validators, according to the blog post. The blog post also notes that rewards are paid in tokens including Pi, rather than in fiat currency as on traditional Web2 platforms.

Result 3: AI-assisted SoloHost app packaging

SoloHost lets developers bring self-hosted applications to Pi Desktop, opening a distribution channel among more than 420,000 Node operators and other Pi Desktop users. Any workload that can be packaged as a Docker image can potentially run in SoloHost. A new AI skill automates this packaging work and is provided in a public repository (github.com/pi-node/solohost). Given an existing application's public Docker image, a compatible AI agent (such as Claude Code, Cursor, or Codex) researches the application's capabilities, asks which settings to offer, generates the two required files (docker-compose.yml and config_options.yml), and validates them against SoloHost's validator. The skill does not build the image itself.

The demo used the AI agent application OpenClaw as an example. The skill researched capabilities including three model providers (Anthropic, OpenAI, and OpenRouter), a Telegram connection, and DuckDuckGo web search, generated the two files reflecting only the capabilities the user selected, corrected an issue flagged by the hosted validator on its own, and ran a local test. Pasting the two generated files into SoloHost published the app, which then ran on Pi Desktop and answered a question about the weather in San Diego.

Result 4: On-chain subscriptions and x402 payments (demonstrated on Testnet)

On-chain subscription smart contracts

Pi's on-chain subscription smart contract lets developers build recurring payment services into their applications. It was first introduced on Pi Testnet in April 2026. A user approves a defined spending budget and subscription period (for example, 6 months for a monthly subscription) without signing every renewal. Approved funds remain in the user's own wallet until each payment is processed, rather than being locked or transferred upfront. Users can extend or cancel their subscriptions. The contract data is managed through two records (the service offering and each user's subscription state) and remains on-chain for around 180 days.

The Day 1 demo created a service priced at 2 Pi per month (service ID 332), showed a user subscribing, and checked the subscription state in the wallet. In the demo example, the merchant could process the next cycle's charge between December 10 and January 10. Subscriptions are currently available only on Testnet. According to the blog post, the supporting infrastructure in Pi Wallet and the developer platform has now been implemented so both users and developers can use the full experience.

x402 payments integrated on Pi Testnet

x402 is an open payment protocol that uses the HTTP 402 (Payment Required) response. A server states the price, asset, and recipient; the client signs a payment approval and resends the request; a facilitator verifies the approval and submits it to the chain. Funds move directly from payer to recipient in a single on-chain transaction, and the facilitator never holds the funds. The standard was created by Coinbase and is maintained by the x402 Foundation.

Pi has made x402 payments available on Pi Testnet. Day 1 featured a demonstration by OpenMind, together with the Fabric Foundation, of its RoboPay platform. A ping command to a robot was paid for with 0.01 Test Pi before the command was delivered, and only after the payment completed. The network fee was sponsored, so the payer's balance changed by exactly minus 0.01 Test Pi. Pi's network ID (pinet) has been merged into the Chain Agnostic registry, and Pi's x402 payment specification has been submitted to the official x402 repository, where it is under review. The specification covers both Testnet and Mainnet, while details on Mainnet availability will be shared later. A Go SDK implementing the specification is also available.

Result 5: Ecosystem initiatives (growth support, app directory, Launchpad)

App Growth Initiative (up to 20 million Pi)

A new initiative sponsored by the Pi Foundation, the "App Growth Initiative", was announced, with a marketing budget of up to 20 million Pi. Eligible developers can qualify for access to a portion of this budget based on the merits and performance of their applications, and use the Pi-funded incentive program to reach and engage KYC-verified users without funding the rewards themselves. As an example, when an eligible KYC-verified Pioneer invites another eligible KYC-verified Pioneer to use a participating app, both the referring Pioneer and the new user could each receive some Pi from the Foundation-sponsored incentive budget for qualifying participation. Exact eligibility requirements and reward amounts will be announced later.

Redesigned Pi App Directory

The Pi App Directory was substantially redesigned. The existing "Ecosystem Directory Staking" mechanism, in which Pioneers stake Pi to support apps and influence ranking, remains central. New discovery sections based on user interest, growth, and engagement were added.

Developer incentives are built from visibility, financial support, and status. As one financial example, Pi App Studio applies subsidized pricing for creators whose apps demonstrate real utility and attract real users. Status is shown in the app directory, and strong apps may gain opportunities such as investment from Pi Network Ventures or candidacy for Launchpad.

Pi Launchpad, DEX, and AMM coming to Mainnet in Q1 2027

Pi Launchpad, decentralized exchange (DEX), and automated market maker (AMM) capabilities will launch on Mainnet in Q1 2027. They have been on Testnet through multiple cycles of iteration, and the launch includes the first Mainnet token launch through Launchpad. They will provide infrastructure for ecosystem token launches for specific utility purposes. The Q1 2027 timeline also gives potential Launchpad candidates, including participants in the upcoming Pi Next hackathon, time to build and prepare.

Other developer features

  • Improved PiNet deep linking: When someone opens a PiNet app link without Pi Browser installed, they are prompted to download Pi Browser from the App Store or Google Play. After installing and opening Pi Browser, they are redirected to the original app or page they intended to visit, so an invited person can play a game session directly without manual navigation.
  • Notification Center: Developers can send users ecosystem notifications from their Pi apps, shown in one place inside the Pi Browser. These are in-app notifications, not push notifications to phones. During the initial rollout, applications can send notifications to up to 20 users without additional approval; notifying more users requires approval. Native push notifications are the next step, subject to more selective and restrictive rules to prevent spam.

CiDi Games is an HTML5 game platform playable directly in the Pi Browser, built around its original character IP "Pi Elf" and its game world "Elf Continent". It has been live for about six months and remains in beta.

For the future, CiDi Games described opening Pi Elf art assets to third-party developers and mapping them onto the blockchain as NFTs, building full-stack tools such as an NFT launchpad and marketplace, and bringing its own native token to Pi Launchpad. These are the company's internal directions, however, and the token plan in particular was stated in the conversation as not yet discussed with the Pi Core Team. They are not confirmed announcements.

CiDi Games also described cooperation with the Pi Core Team, including a case in which players' KYC-related questions led to KYC survey questions being arranged and launched in less than two weeks. Fixes for iOS local-storage issues, a streamlined Mainnet verification process for new releases, and per-team advertising reporting were likewise made in response to developer feedback.

Fan described the broader strategy as connecting external demand to Pi's collective resources (distribution, attention, and user acquisition; human-in-the-loop work and data, with user consent; distributed computing; and identity). Gaming fits Pi well, she said, because payments run at scale on-chain, social interaction matches gaming, and games offer an easy on-ramp to financial participation. Stablecoin integration and further Web3 functionality are being considered within limits that do not compromise the central role of the Pi currency.

Following the conversation, a technical demo showed how the CiDi Games gaming platform integrates Pi's developer tools. It covered Pi Authentication (sign-in), Pi Payments, the Pi Ads SDK, and local storage. The demo used a locally running sample to walk through the official SDK procedures, rather than a live production environment; this was stated repeatedly in the video.

For authentication, the demo requested the username and payment scopes, received Pi's authentication result (an access token and a user object), and linked it to an application account. It was explained that a Pi user identifier is specific to each application — not a universal identifier shared by all Pi apps — and that it may change when the user revokes permissions. Importantly, CiDi Games' current backend does not yet call Pi to verify the access token, and this was shown separately from the recommended procedure (sending the token to the backend and requesting the user resource from Pi to compare identifiers). It is not a claim that identity verification is performed in production.

For payments, the demo showed a top-up of the platform currency CDcoin: a 100-coin top-up, moving the balance from 101 to 201. It distinguished the approval, completion, and duplicate-protection stages, crediting coins only after completion is confirmed, and described a recovery flow that queries unfinished payments when a browser is closed mid-payment. The Pi amount shown was an illustrative quote in the sample, not a current exchange rate.

For ads, the demo used a rewarded advertisement to make up a missed daily check-in. Watching the ad alone does not grant the reward: the backend queries Pi for the ad's status, and the reward is granted only when the mediator acknowledgement status is "granted". A pending, revoked, or failed status does not authorize the reward. Each ad identifier is accepted only once, preventing duplicate claims.

For local storage, the demo used a language preference (switching from English to Japanese) to show that a setting is saved in the browser and restored on relaunch. Storage is device-specific and does not guarantee cross-device synchronization or permanent storage. It was also stated in the video that CiDi Games' whitelist status for local storage access still needs confirmation.

The demo also described a shared game SDK and common verification service that lets multiple games reuse the same integration. Meme War and Ian Reap were named as examples. However, the spelling of both titles rests on the subtitles alone and could not be confirmed against official material.

Result 7: Developer conversation (Resonant) — human participation in the AI and data economy

Founder Chengdiao Fan spoke with Jay of the AI project Resonant. Resonant is a verification layer for AI decisions: it collects human decisions on ethical dilemmas (for example, whom a domestic robot should save in a fire) and their metadata, to measure whether AI agents decide the way humans would. About 1.7 million decisions have been collected so far, and Jay said the data becomes considerably more valuable at 15 million decisions (based on the spoken remarks alone).

The conversation covered data as an important productive resource of the AI economy, Pi DataLab as the link between that demand and Pioneers, AI agents distributed through SoloHost on Pi Desktop or as Pi apps, and the value of Pi's identity-verified user base in proving humanness and lowering onboarding barriers for AI companies. Jay said Resonant chose Pi for its global user exposure and for one-click, identity-verified sign-in that lowers user-acquisition costs.

As advice for developers, Jay shared that writing an app in English only reaches about 40% of Pi's users, and that native translation increased user uptake two to three times (based on the spoken remarks alone). Pi's users speak nine languages, he said.

Resonant's future direction includes presenting questions in video form, collecting decision data in a way that is entertaining. Users hold their own decision profile — their own data — which they can link to agents and, in the future, connect to mechanisms for monetizing their data. Resonant is currently a non-profit research verification layer, and its metadata is published without personal detail.

Fan explained a plan to separate the Testnet and Mainnet distinction from the app-listing process. Listing in the app directory will be simplified as a single process, with the Testnet/Mainnet distinction applying only to operations involving wallets, such as payments.

The Resonant app in the Pi Browser was mentioned at the close of the video, but its exact URL could only be heard from the subtitles and is unconfirmed.
