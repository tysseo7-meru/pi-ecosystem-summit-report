Day 2：AIとエコシステム（11月18日）

Day 2（11月18日）のテーマは「AIとエコシステム」である。本編動画は Pi Network 公式YouTubeチャンネルでプレミア公開され、長さは1時間34分11秒である。内容は、Pi DataLab の紹介、SoloHost のAIスキルによる実演、CiDi Games の技術デモ、創業者チェンディアオ・ファンとAIプロジェクト Resonant のジェイ氏による対話である。

結果6：Pi DataLab（人間の判断をAIにつなぐ新プラットフォーム）

Pi DataLab は、企業・AI開発者・団体が、本人確認済みの世界中のパイオニアに、人間の判断を要する作業を依頼できる新しいヒューマン・イン・ザ・ループ型プラットフォームである。AIの学習・評価・改善に必要なデータ生成、ラベル付け、評価、順位付け、レビュー、フィジカルAI向けデータなど、人間の理解が要る作業が対象である。依頼側はプロジェクトを作成して資金を用意し、参加するパイオニアは自発的に作業を選び、判断や作業を提供して、完了した貢献に対して Pi またはトークンを受け取る。

デモでは、顧客対応チケットの感情分類（肯定的・中立的・否定的）を例に、プロジェクト作成から公開までの流れを示した。プロジェクト名「ticket sentiment」、作業ごとに5件の回答を求める設定、KYC済みであること・言語・地域などの参加条件を設定し、Piの審査を経て公開される。公開後は、作業の開始・完了までの平均時間や承認率などの指標を確認できる。作業者側にはタスクのマーケットプレイスが表示され、報酬と所要時間の目安を確認して作業を選ぶ。報酬は月払いである（デモ中の説明による）。

品質の仕組みとして、作業者の評判が記録される。努力の有無、作業の開始・完了にかかる時間、提出回数、正答率などが信号となり、質の維持と将来の作業の割り当てに使われる。

初版は完成し、テスト環境で動作している。デモはテスト環境で行われ、決済は有効化されていない。公開されるパイロット版では、メインネットのウォレットを通じた決済がつながる見込みである。公開時期は明示されていない。

背景として、PiのKYC検証の仕組みは、100万人超の本人確認済みの検証者が5億2,600万件超の検証作業を完了した実績がある（ブログ記事による）。ブログ記事は、報酬が法定通貨ではなく Pi を含むトークンで支払われる点を、従来のWeb2型プラットフォームとの違いとして説明している。

結果7：SoloHost のAIスキル（既存アプリの包装を自動化）

SoloHost は、開発者が自己ホスト型アプリを Pi Desktop へ持ち込み、42万人超のノード運営者と Pi Desktop 利用者に配布できる仕組みである。Dockerイメージとして包装できる作業負荷であれば、SoloHost 上で動作する可能性がある。新しいAIスキルは、この包装作業をAIエージェントに任せるためのものであり、公開リポジトリ（github.com/pi-node/solohost）で提供されている。対応するAIエージェント（Claude Code、Cursor、Codexなど）に既存アプリの公開Dockerイメージを示すと、エージェントがアプリの機能を調べ、必要な設定を尋ね、包装に必要な2つのファイル（docker-compose.yml と config_options.yml）を生成し、SoloHost の検証プログラムで確認する。イメージ自体の構築はスキルでは行わない。

デモでは、AIエージェントアプリ OpenClaw を例に、スキルが3つのモデル提供者（Anthropic、OpenAI、OpenRouter）と Telegram 連携、DuckDuckGo によるウェブ検索などの機能を調べ、利用者が選んだ機能だけを反映した2つのファイルを生成し、検証プログラムの指摘を自ら修正したうえで、ローカルでの動作確認まで行う流れを示した。生成した2つのファイルを SoloHost へ貼り付けて公開すると、Pi Desktop 上でアプリが動作し、天気の質問に回答した。

結果8：CiDi Games の技術デモ（Pi認証・Pi決済・Pi広告）

Day 1 の対話に続き、CiDi Games のゲームプラットフォームが Pi の開発者ツールとどのように統合されるかを、技術デモで示した。対象は Pi認証（サインイン）、Pi決済、Pi広告SDK、ローカルストレージである。デモは、実際の本番環境ではなく、ローカルで動作する見本（サンプル）を用いて、公式SDKの手順をなぞる形で行われた。見本であることは動画の中で繰り返し明示されている。

認証では、ユーザー名と決済の範囲を要求し、Piの認証結果（アクセストークンとユーザー情報）を受けて、アプリ側のアカウントと結びつける流れを示した。Piのユーザー識別子はアプリごとに異なるものであり、すべてのアプリで共通の識別子ではないこと、権限を取り消すと変わり得ることが説明された。重要な点として、CiDi Games の現在のバックエンドは、アクセストークンを Pi に問い合わせて検証する手順をまだ実装しておらず、公式の推奨手順（トークンをバックエンドへ送り、Pi へユーザー情報を問い合わせて照合する）とは区別して示された。本番環境で検証が行われているという主張ではない。

決済では、プラットフォーム通貨 CDcoin へのチャージを例に、100コインのチャージ（残高101から201へ）を示した。決済の承認・完了・重複防止の各段階を区別し、完了が確認されて初めてコインを付与すること、ブラウザを閉じて決済が中断した場合には未完了の決済を照会して回収する仕組みが説明された。表示された Pi の金額は見本の目安であり、実際の為替相場ではない。

広告では、リワード広告を例に、見逃した毎日のチェックインを広告視聴で補う流れを示した。広告の視聴だけでは報酬は付与されず、バックエンドが Pi へ広告の状態を問い合わせ、仲介者の承認状態（mediator acknowledgement status）が「granted」である場合にのみ報酬が付与される。保留中（pending）や取り消し・失敗では付与されない。広告識別子は一度だけ有効であり、重複請求は防がれる。

ローカルストレージでは、言語設定（英語から日本語への切り替え）を例に、設定がブラウザに保存され、再起動後に復元されることを示した。端末ごとの保存であり、端末間の同期や恒久的な保存を保証するものではない。また、CiDi Games のローカルストレージ利用の承認（ホワイトリスト）状態は未確認であり、動画の中でも確認が必要であることが明言された。

共有のゲームSDKと共通の検証サービスにより、複数のゲームが同じ統合の仕組みを使い回す設計も説明された。例として Meme War と Ian Reap が挙げられた。ただし、両タイトル名の表記は字幕のみが根拠であり、公式資料での裏付けはできていない。

結果9：開発者対話（Resonant）― AIとデータの経済における人間の参加

創業者チェンディアオ・ファンと、AIプロジェクト Resonant のジェイ氏による対話があった。Resonant は、AIの判断を人間の判断と照らし合わせるための検証層である。人間が倫理的なジレンマ（例：家庭用ロボットが火災時に誰を助けるか）に対して下す判断と、その判断のデータを集め、AIエージェントが人間の判断と一致しているかを測る。現在までに約170万件の判断が集まっており、1,500万件に達すればデータがさらに価値を持つと説明された（発言のみが根拠）。

対話では、データがAI経済における重要な生産資源であること、Pi DataLab がその需要とパイオニアをつなぐ役割を果たすこと、AIエージェントが Pi Desktop 上で動作する SoloHost や Piアプリとして配布できること、Piの本人確認済みユーザー基盤が、AI企業にとって人間の証明とオンボーディングの障壁を下げる価値があることが語られた。Resonant が Pi を選んだ理由として、世界中のユーザーへの露出と、ワンクリックでの本人確認済みログインによる利用者獲得コストの低さが挙げられた。

また、開発者への助言として、アプリを英語のみで書くと利用者の約40%にしか届かず、ネイティブ翻訳により利用者の取り込みが2〜3倍になるという経験が紹介された（発言のみが根拠）。Piの利用者は9言語を使っていると説明された。

Resonant の今後の方向性として、質問を動画形式で提示するなど、楽しさを伴う形で判断データを集めることが語られた。利用者は自分の判断プロフィール（自分のデータ）を持ち、エージェントと結びつけたり、将来的にはデータの収益化の仕組みにつなげたりすることが想定されている。現在の Resonant は非営利の研究用検証層であり、データは詳細を含まず公開されている。

ファンは、テストネットとメインネットの区別をアプリ一覧の掲載手続きから切り離す方針を説明した。アプリの掲載は一覧の手続きとして簡素化し、テストネット／メインネットの区別は決済などウォレットを伴う操作に限る方向である。

Resonant アプリの利用先として、動画の締めくくりで Piブラウザ内のアプリが紹介されたが、正確なURLは字幕の聞き取りのみで確認できず、未確認である。
